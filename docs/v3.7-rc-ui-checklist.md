# V3.7 RC Telegram UI acceptance

These flows are registered in `bot.py`. No real Telegram account or bot token
was available during the offline RC audit. A human tester should record each
result after a controlled Docker Compose deployment. Do not use a real customer
order for the write paths.

| Role | Flow | Expected observation | Status |
|---|---|---|---|
| User | `/start` | User home buttons appear | NOT TESTED |
| User | Buy new subscription | Plan list and payment choice appear when Panel configuration is ready | NOT TESTED |
| User | Submit payment proof | Pending order appears; no subscription is delivered before admin approval | NOT TESTED |
| User | My orders | Own order list and status are visible; other users' orders are inaccessible | NOT TESTED |
| User | My subscription | Only numeric-ID-linked subscriptions open; unresolved legacy links request admin review | NOT TESTED |
| User | Subscription details and QR | Expiry, traffic and the user's subscription QR render without exposing another user's link | NOT TESTED |
| User | Renew | Existing subscription and plan are selected; approval extends the same Panel user ID | NOT TESTED |
| User | Node status | Node `isConnected` status displays correctly | NOT TESTED |
| User | Contact support | Message routing and exit control work | NOT TESTED |
| Admin | `/start` | Admin console appears only to the configured admin ID | NOT TESTED |
| Admin | Panel user lookup and legacy binding | Numeric ID lookup works; ambiguous old records require exact manual selection | NOT TESTED |
| Admin | Plan management | Add, view and delete affect only the intended local plan | NOT TESTED |
| Admin | Order audit and approval | Pending, failed and delivered states are accurate; retry does not create a second Panel user | NOT TESTED |
| Admin | Node and bandwidth views | Accessible nodes and seven-day bandwidth display official response fields | NOT TESTED |
| Admin | Batch actions and task list | Numeric user IDs queue; accepted 202 tasks say submitted, uncertain work says unknown | NOT TESTED |
| Admin | Panel and subscription configuration | Saved UI settings persist; `.env`-owned secrets cannot be silently overridden | NOT TESTED |
| Admin | System Panel dashboard | Health, stats and recap load without showing tokens | NOT TESTED |
| Admin | Anomaly settings and whitelist | Numeric user IDs and alert controls work | NOT TESTED |

Record failures with the callback or command, timestamp, sanitized container
log excerpt and expected/actual result. Never record a token, subscription URL,
payment proof or personal data in this checklist.
